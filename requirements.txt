# Pinned dependencies for the SoAI 2026 submission.
#
# WHY PINNED: the competition brief requires "All deps pinned in
# requirements.txt", and the template README warns that "missing or
# pinned-incompatible dependencies will cause your submission to be skipped".
# That failure is SILENT - no error comes back to us, we simply do not appear
# on the leaderboard. Lumibot shipped 12 releases in the month before the
# deadline (4.5.70 -> 4.5.83), so an unpinned `lumibot` could install a version
# on the organizers' machine that never existed when we tested.
#
# WHY NOT A FULL `pip freeze`: resolving this file pulls 308 packages. Freezing
# all of them would (a) pin macOS/arm64-resolved versions that may have no wheel
# on the organizers' Linux x86_64 box, and (b) turn every transitive bump into a
# hard conflict. Instead we pin the packages we actually import and let
# lumibot's own metadata constrain its tree - which it does properly
# (numpy<2.5.0, pandas>=2.2.0, ccxt>=4.5.50, ...).
#
# INTERPRETER SENSITIVITY (measured 2026-08-05): the resolved tree differs by
# Python version. google-adk (a lumibot dependency) pulls `crewai[tools]` behind
# the marker `python_version >= "3.11" and python_version < "3.12"`, dragging in
# crewai, chromadb, lancedb, onnxruntime, pymupdf and friends. Result:
#     Python 3.11 -> 308 packages, cold install ~12 min (heavy pip backtracking,
#                    crewai alone probed in 36 versions)
#     Python 3.12 -> 268 packages, cold install ~95 s, no meaningful backtracking
# Both resolve and both pass the suite, so these pins are safe either way - but
# we develop on 3.12 for the faster, leaner, more deterministic tree.
#
# Verified: Python 3.12.7, macOS arm64, `python backtest.py` exit 0, 10/10 tests.
# Also verified on Python 3.11.14. CI re-verifies on Linux across 3.10-3.13.

# --- Core framework (required entrypoint: lumibot.strategies.Strategy) -------
lumibot==4.5.83

# --- Numerics: signal computation and portfolio construction ----------------
pandas==2.3.3

# numpy is split by interpreter because 2.4.x requires Python >=3.11 and simply
# does not exist for 3.10 (newest 3.10-compatible release is 2.2.6). A flat
# `numpy==2.4.6` made `pip install -r requirements.txt` FAIL OUTRIGHT on Python
# 3.10 -- and since the brief's failure mode for a bad environment is a silent
# skip, that would have been an invisible disqualification if the organizers
# happen to run 3.10. Caught by CI, not by reading. Both pins satisfy lumibot's
# own numpy<2.5.0,>=1.20.0 constraint, and both are exact, so the file stays
# fully pinned as the rules require.
numpy==2.4.6; python_version >= "3.11"
numpy==2.2.6; python_version < "3.11"

# --- Exchange data adapter (crypto spot OHLCV). Arrives as a lumibot
# transitive, pinned explicitly so local research data is reproducible. -------
ccxt==4.5.64

# --- REMOVED: scikit-learn. It came from the upstream template and nothing in
# this repo imports it. It also required Python >=3.11, so it was a second
# reason the install broke on 3.10. Dropping an unused dependency is strictly
# better than pinning around it: every package we carry multiplies the chance of
# a resolution conflict in an environment we cannot inspect. Reinstate only if a
# model-based candidate actually earns its place. ---------------------------

# --- Retained from the upstream template; lumibot imports it. ---------------
python-dotenv==1.2.2
